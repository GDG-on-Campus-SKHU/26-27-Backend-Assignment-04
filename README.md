# Spring Security & JWT 과제

## 과제 설명

현재 실습 프로젝트의 JWT 필터는 토큰을 검증한 뒤, 모든 사용자에게 `ROLE_USER` 권한을 부여하고 있습니다.

따라서 로그인한 사용자는 구분할 수 있지만, 일반 사용자와 관리자는 구분하지 못합니다.

이번 과제에서는 사용자 역할을 추가하고, 관리자만 접근할 수 있는 API를 구현해 주세요.

또한 기존 게시글 삭제 API를 수정해 게시글 작성자 또는 관리자만 삭제할 수 있도록 수정해 보세요.

게시글 삭제 API 수정은 선택사항이므로, 필수로 구현하지 않아도 괜찮습니다.

---

## 과제 요구사항

### 1. 사용자 역할

- 사용자 역할은 `USER`, `ADMIN` 두 가지여야 합니다.
- 일반 회원가입으로 생성되는 계정의 역할은 항상 `USER` 이어야 합니다.
- 관리자 계정은 외부 요청으로 생성할 수 없어야 하며, db에 직접 관리자 계정을 추가하거나, 초기 데이터 코드로 생성할 수 있습니다.

### 2. JWT와 Spring Security

1. 서버에 저장된 사용자 역할을 Access Token의 claim에 담아야 합니다.
2. Refresh Token을 Access Token처럼 사용해서는 안 됩니다.
3. Refresh Token으로 토큰을 재발급해도, 사용자의 역할이 새 Access Token에 그대로 반영되어야 합니다.
4. 비밀번호는 항상 `PasswordEncoder`를 사용해 인코딩 후 저장해야 합니다.

### 3. 관리자 전용 API

`GET /admin/me`를 구현합니다.

```json
{
    "id": 1,
    "email": "test1234@test.com",
    "isAdmin": true
}
```

- 관리자라면 200 OK, 응답 바디가 반환되어야 합니다.
- 로그인하지 않은 사용자라면 401 Unauthorized가 반환되어야 합니다.
- 로그인했지만 관리자가 아닌 경우 403 Forbidden이 반환되어야 합니다.

### 4. 오류 응답

401과 403을 포함한 실패 응답은 지난 강의와 이번 강의에서 사용한 `ErrorResponse` 형식을 따라주세요.

```json
{
  "code": "AUTH_006",
  "message": "접근 권한이 없습니다."
}
```

관리자 API의 권한 부족을 나타낼 수 있는 Error Code를 추가해주세요.

기존 게시글 소유자 권한 오류 메시지와 구분할 수 있어야 합니다.

### 5. 게시글 삭제 권한 (선택)

기존 `DELETE /posts/{postId}`를 다음과 같이 변경해주세요.

- 게시글 작성자: 삭제 가능, 204 반환
- 관리자: 모든 글 삭제 가능, 204 반환
- 작성자가 아닌 일반 사용자: 403 Forbidden
- 존재하지 않는 게시글: 404 Not Found

## Postman 확인 항목

### 필수

| 상황 | 응답 |
| --- | --- |
| 토큰 없이 `GET /admin/me` | 401, 적절한 오류 코드 |
| 일반 사용자의 Access Token으로 `GET /admin/me` | 403, 새로 정의한 관리자 권한 오류 코드 |
| 관리자의 Access Token으로 `GET /admin/me` | 200, 관리자 정보 |
| Refresh Token을 Bearer Token으로 넣고 `GET /admin/me` | 401 |

### 선택

| 상황 | 예상 응답 |
| --- | --- |
| 게시글 작성자가 자신의 글 삭제 | 204 |
| 다른 사람의 글 삭제 | 403, 적절한 오류 코드 |
| 관리자가 다른 사람의 글 삭제 | 204 |
| 존재하지 않는 게시글 삭제 | 404 |

## 힌트

1. `User`에 역할을 저장할 필드를 추가하고, 일반 회원가입에서는 서버가 직접 `USER`를 지정해 보세요. 회원가입 요청값으로 역할을 결정하면 안 됩니다.
2. Access Token을 만들 때 DB에 저장된 역할을 claim에 넣어 보세요. 재발급할 때도 서버가 확인한 사용자 역할로 새 Access Token을 만들어야 합니다.
3. 현재 `JwtAuthenticationFilter`는 `ROLE_USER`를 고정으로 넣습니다. 검증된 Access Token의 역할에 따라 `GrantedAuthority`를 설정해 보세요. `hasRole("ADMIN")`은 기본적으로 `ROLE_ADMIN` 권한을 확인합니다.
4. 관리자 API 접근 규칙은 `SecurityConfig`의 `anyRequest().authenticated()`보다 앞에 작성해야 합니다.
